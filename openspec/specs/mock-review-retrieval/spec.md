# mock-review-retrieval Specification

## Purpose

외부 DB 없이 로컬 샘플 리뷰(CSV)를 적재하고 질문과 관련된 리뷰를 점수와 함께 검색하며 대화 기록을 보관한다. 실데이터 모드의 검색·저장소가 대체할 데이터 접근 계약이다.

## Requirements

### Requirement: 샘플 리뷰 적재
시스템은 샘플 리뷰 CSV 의 전체 행을 읽어 서버 메모리에 보관하고 적재된 건수를 반환해야 한다(SHALL). 같은 서버 프로세스에서 반복 적재해도 건수는 동일해야 하며 리뷰가 중복 저장되어서는 안 된다(MUST NOT).

#### Scenario: 최초 적재
- **WHEN** 적재를 요청한다
- **THEN** CSV 의 리뷰 건수(샘플 기준 100)가 반환되고 이후 검색 대상이 된다

#### Scenario: 반복 적재
- **WHEN** 이미 적재된 상태에서 다시 적재를 요청한다
- **THEN** 같은 건수가 반환되고 검색 결과에 중복 리뷰가 나타나지 않는다

#### Scenario: CSV 읽기 실패
- **WHEN** CSV 파일이 없거나 형식이 잘못되어 읽을 수 없다
- **THEN** 적재는 오류로 끝나고 호출자가 실패 사유를 알 수 있다

### Requirement: 질문 키워드 추출
검색은 질문을 공백으로 나눈 토큰에서 조사·구두점을 제거하고 2글자 이상인 토큰만 키워드로 사용해야 한다(SHALL).

#### Scenario: 조사가 붙은 질문
- **WHEN** 질문이 "배터리가 오래가나요?" 이다
- **THEN** 키워드에서 구두점과 조사가 제거되어 "배터리" 로 리뷰의 제목과 내용에 매칭된다

#### Scenario: 한 글자 토큰
- **WHEN** 질문에 한 글자 토큰이 포함된다
- **THEN** 그 토큰은 키워드로 사용되지 않는다

### Requirement: 키워드 기반 상위 K건 검색
검색은 각 리뷰의 제목과 내용에서 키워드가 포함된 횟수와 도움됨 수(`helpful_votes`)를 함께 반영해 점수를 계산하고, 점수가 높은 순으로 최대 K건(기본 5)을 반환해야 한다(SHALL). 키워드가 하나라도 매칭된 리뷰만 결과에 포함되어야 한다(MUST).

#### Scenario: 매칭되는 리뷰가 K건 이상
- **WHEN** 키워드가 여러 리뷰에 매칭된다
- **THEN** 점수 내림차순으로 정확히 K건이 반환된다

#### Scenario: 매칭 횟수와 도움됨 수 반영
- **WHEN** 두 리뷰의 키워드 매칭 횟수가 같고 도움됨 수가 다르다
- **THEN** 도움됨 수가 많은 리뷰가 더 높은 순위로 반환된다

#### Scenario: 매칭되는 리뷰가 K건 미만
- **WHEN** 키워드가 K건보다 적은 리뷰에만 매칭된다
- **THEN** 매칭된 리뷰만 반환되고 무관한 리뷰로 채우지 않는다

### Requirement: 점수 정규화
반환되는 각 리뷰의 유사도 점수는 0.65 이상 0.98 이하 범위로 정규화되어야 하며(MUST), 순위가 높을수록 점수가 작아져서는 안 된다(MUST NOT).

#### Scenario: 점수 범위
- **WHEN** 어떤 질문으로든 검색한다
- **THEN** 반환된 모든 리뷰의 점수가 0.65 이상 0.98 이하이다

#### Scenario: 점수 순서
- **WHEN** 검색 결과가 둘 이상이다
- **THEN** 결과 목록의 점수는 내림차순이다

### Requirement: 매칭 없음 시 기본 결과
키워드가 하나도 매칭되지 않거나 키워드를 추출할 수 없으면 도움됨 수가 높은 리뷰 상위 K건을 기본 결과로 반환해야 한다(SHALL). 기본 결과의 점수도 정규화 범위를 따라야 한다(MUST).

#### Scenario: 무관한 질문
- **WHEN** 질문의 어떤 키워드도 리뷰에 나타나지 않는다
- **THEN** 도움됨 수가 높은 순으로 K건이 반환된다

#### Scenario: 키워드 없는 질문
- **WHEN** 질문이 한 글자 토큰이나 기호로만 이루어져 있다
- **THEN** 도움됨 수가 높은 순으로 K건이 기본 결과로 반환된다

### Requirement: 검색 전 자동 적재
적재가 아직 수행되지 않은 상태에서 검색을 요청해도 시스템은 샘플 리뷰를 먼저 적재한 뒤 검색해야 한다(SHALL).

#### Scenario: 인덱싱 없이 질문
- **WHEN** 사용자가 [샘플 데이터 인덱싱] 없이 질문을 보낸다
- **THEN** 리뷰가 자동으로 적재되고 정상적인 검색 결과가 반환된다

### Requirement: 대화 메시지 저장과 조회
시스템은 대화(chatId)별로 메시지(역할, 내용, 시각)를 서버 인메모리에 순서대로 저장하고 조회할 수 있어야 한다(SHALL). 다른 chatId 의 메시지가 섞여서는 안 된다(MUST NOT).

#### Scenario: 메시지 저장 후 조회
- **WHEN** 같은 chatId 로 사용자 메시지와 AI 메시지를 차례로 저장한 뒤 조회한다
- **THEN** 저장한 순서대로 두 메시지가 반환된다

#### Scenario: 대화 분리
- **WHEN** 서로 다른 chatId 로 메시지를 저장한다
- **THEN** 각 chatId 의 조회 결과에는 자신의 메시지만 포함된다

#### Scenario: 서버 재시작
- **WHEN** 서버 프로세스가 재시작된다
- **THEN** 저장된 메시지는 사라진다(영속화하지 않음)
